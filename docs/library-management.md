# 图库与文件管理

Aurora 使用自己的可移植目录格式。行为参考 Capture One 的 Library、Folders、Sessions、Albums 和 Smart Albums；不写入 Capture One 的数据库。

## 使用

- 文件 → 新建目录（Ctrl+Shift+N）或新建会话（Ctrl+N）：输入名称，再选择父文件夹。目录建立 Originals；会话建立 Capture、Selects、Output、Trash。
- 从“打开目录”选择 `library.auroracatalog` 或 `session.aurorasession`，也可直接打开其父文件夹。每个文档在自己的窗口打开。
- 图库的“系统文件夹”按需展开磁盘目录，选择目录直接浏览。“文件夹”显示当前图库引用的磁盘位置；“包含子文件夹”控制选中目录的浏览范围。
- 右键文件夹可新建子目录、重命名、移动、同步、定位、收藏和在资源管理器中显示。会话可将目录设为 Capture / Selects / Output / Trash；Output 连接导出配方，Capture 连接联机拍摄目标。
- 缩略图和列表行右键可移动照片、重命名、批量重命名、移至精选、移入/恢复目录废纸篓，以及从目录移除。拖到相册只改变归类；拖到真实文件夹会移动原片。
- 导入支持保留原位引用、复制到目的位置、备份、重命名、元数据、风格、加入相册，以及取消后续文件。默认跳过重复文件；取消跳过后使用无冲突编号，不覆盖已有文件。两种常见 XMP 文件命名随原片复制。
- 离线文件保留编号、调整、评级、关键词和集合关系；已有缓存时可浏览缓存预览。右键离线缩略图“定位原始文件”连接单张原片，或在文件夹树中“定位文件夹”连接整批文件。
- 项目内的智能相册只搜索该项目的普通相册成员。组内的智能相册不自动限制搜索范围。相册、项目和组可以在集合对话框中移动；拒绝循环及嵌套项目。

## 原片和编辑记录

移动、重命名会一起处理原片和 XMP，并保留所有变体的身份。执行前检查同名目标、目录边界和已有引用；失败时尝试回退，回退失败会明确报告路径。图库变更在后台执行，成功后刷新界面。

“从目录移除”和“清空目录废纸篓”移除图库里的变体与调整，不删除磁盘原片。再次显式导入或同步可重新导入已移除的原片。当前版本的目录废纸篓是逻辑废纸篓，Session 的 Trash 快捷目录不等于系统回收站。

新目录格式为 schema 2，可读取旧 schema 1。首次升级保留 `catalog.schema1.backup.json`；调整文件也可能独立升级，单独恢复该备份不构成完整降级。旧版应用不应继续写入升级后的目录。

## 当前边界

- 离线预览来自最近保存的缩略图，不能冒充全分辨率 RAW。离线时调整会保存，重新连接后才呈现新的像素效果；导出仍需原片。
- 整个文件夹跨盘移动当前明确报错；单文件跨盘移动由 Windows 文件系统接口处理。网络盘、权限变化、断电或进程被强制结束不属于本轮原子事务的完整保证。
- 未实现 Capture One 原生目录的反向写入、目录合并/拆分/导出、目录模板、文件夹监控服务或从磁盘永久删除入口；不宣称全部 Capture One 功能一比一完成。

## 开发与验证

- 相册与文件夹必须区分虚拟关系和物理位置。所有前端管理入口通过 ImageEngine 的 LibraryAction；不在 UI 中另写移动/删除逻辑。
- ImageId 与调整存储键在重扫、移动、定位和重启后保持稳定，不使用目录遍历顺序生成已有图像身份。
- 原片不可覆盖；批处理先检查完整计划。任何持久化失败不得让界面显示为成功；不能将路径不存在解释为主动移除。
- 默认测试仅使用临时合成图片；不要拿用户照片做移动、删除、重命名测试。
